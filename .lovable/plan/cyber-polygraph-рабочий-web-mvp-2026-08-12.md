# Cyber-Polygraph — рабочий Web MVP

Референс механики — Rizz app (вставил переписку → получил готовый ответ для копипаста), но сегмент другой: не свидания, а конфликты и власть в переписке.

## 1. Сегмент и отстройка от Rizz

**Rizz:** флирт, знакомства, "как понравиться".
**Мы:** переписки, где тебя дожимают — и надо не понравиться, а не проиграть.

Позиционирование: **"Тактический декодер переписок"**. Не ассистент, а разведка + контрудар.

Основные сценарии (ядро продукта):
- Работа: босс/коллега перекладывает вину, давит дедлайном, газлайтит по договорённостям.
- Клиенты/фриланс: торг, обесценивание, "мы же договаривались по-другому", неоплата.
- Личное: партнёр/бывший, обвинения, манипуляция виной, холодное молчание.
- Публичное: токсичные комменты, наезды в чатах, где важно ответить спокойно и убийственно.

Ключевое отличие в выдаче: Rizz даёт одну строчку-подкат. Мы даём **разбор + позицию + ответ**:
1. Что на самом деле делает отправитель (паттерны манипуляции).
2. Его слабое место / чего он на самом деле хочет.
3. 3 варианта ответа под разные тоны: **Холодный профи / Жёсткая граница / Спокойный добивающий** — каждый копипастом.

## 2. Как продукт даёт реально хорошие ответы

Ничего "обучать" (fine-tune) на MVP не нужно и не стоит — качество даёт не дообучение, а сильный промпт + структурированный выход + сильная модель.

- **Модель:** GPT-5.6 через встроенный AI-шлюз Lovable (ключей и аккаунтов заводить не надо, поддерживает и текст, и картинки — то есть скриншоты сразу). Claude/Gemini как альтернативы не дают тут выигрыша, а усложняют инфраструктуру.
- **Скриншоты:** та же модель читает изображение — загрузил скрин переписки, она сама вытаскивает реплики и понимает, кто есть кто. Отдельный OCR не нужен.
- **Системный промпт-профиль** под наш сегмент: роль переговорщика/поведенческого аналитика, словарь тактик (guilt-trip, газлайтинг, ложная срочность, moving goalposts, обесценивание, silent treatment, скрытая угроза), жёсткие правила тона: без оскорблений, без истерики, короткие фразы, факты и границы, ответ должен быть отправляем как есть.
- **Строгая схема ответа** (JSON) → фронт всегда получает одинаковые блоки, ничего не парсим вручную и не ломаем вёрстку.
- **Контекст от пользователя** — минимальный, один чип-выбор: *Работа / Клиент / Отношения / Публичный спор*. Это заметно поднимает точность и не требует квиза.
- **Качество итерируем** на наборе из ~20 реальных кейсов: гоняем промпт, правим формулировки в системном промпте. Это и есть "обучение" на MVP.

## 3. Монетизация без подписки и без квиза

Модель: **разовый платёж за разблокировку + пакеты "декодов"** (pay-per-use), под уже готовый paywall-экран.

- Первый скан — бесплатно до момента результата: показываем разбор угроз (счётчики, названия паттернов) — закрыт только **сам текст ответов**. Ценность доказана до оплаты.
- Разблокировка — разовая покупка пакета:
  - **1 декод — 4.99$** (импульс, минимальный барьер)
  - **10 декодов — 14.99$** (рекомендуемый, "выгодно")
  - **50 декодов — 39.99$** (для тех, у кого война надолго)
- Никакого автосписания и триала → меньше страха на вебе, оплата в 1 экран.
- Возврат пользователя: остаток декодов живёт в аккаунте (вход по email-ссылке) — это и есть причина вернуться, вместо подписки.
- Апсейл позже (не в MVP): "Досье на отправителя" — накопленный профиль по одному человеку через несколько переписок.

Оплату включаем встроенным платежным модулем Lovable (Stripe без своего аккаунта), Checkout в новой вкладке, вебхук начисляет декоды.

## 4. Что строим (объём MVP)

1. Ввод: текст **или** скриншот (загрузка/paste), чип-выбор контекста.
2. Существующая 8-секундная анимация скана остаётся, но теперь она ждёт реальный ответ AI.
3. Paywall-экран: реальные данные (сколько паттернов нашли, их названия), ответы скрыты блюром.
4. Экран результата: разбор + мотив + 3 варианта ответа с "копировать".
5. Аккаунт: вход по email-ссылке, баланс декодов, история сканов.
6. Оплата: 3 пакета, Checkout, начисление по вебхуку.

Визуал, дизайн и копирайтинг текущих экранов не трогаем — только добавляем недостающие элементы в том же стиле.

## 5. Техническая часть

- Бэкенд: Lovable Cloud (БД + аккаунты + хранение скриншотов).
- Таблицы: `profiles` (баланс декодов), `scans` (входной текст/скрин, результат JSON, оплачен ли), `purchases` (пакеты, вебхук Stripe). RLS: каждый видит только своё.
- AI-вызов — серверная функция (ключ никогда не уходит в браузер), потоковый вызов через Responses API, строгая JSON-схема результата.
- Системный промпт — отдельный серверный модуль, чтобы его удобно было итеративно докручивать.
- Разблокировка проверяется на сервере: полный текст ответов не уходит в браузер, пока скан не оплачен.

## 6. Порядок работ

1. Включаем Cloud, схема БД, аккаунты.
2. Серверный анализ (текст) + промпт-профиль → подключаем к текущему флоу.
3. Скриншоты как вход.
4. Paywall на реальных данных + экран результата с 3 ответами.
5. Платежи: пакеты, Checkout, вебхук, списание декодов.
6. Прогон на реальных кейсах и докрутка промпта.
